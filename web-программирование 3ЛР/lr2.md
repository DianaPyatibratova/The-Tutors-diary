# Лабораторная работа №2

## Тема
Интерактивный Frontend и State-Driven SPA.

## Цель работы
Научиться работать с JavaScript, DOM, событиями, формами, состоянием приложения и локальным хранилищем браузера.

## Тема проекта
Дневник репетитора.

## Описание проекта
В лабораторной работе был доработан сайт «Дневник репетитора», созданный в первой лабораторной работе.

Пользователь может:
- искать учеников;
- фильтровать учеников по предмету;
- сортировать учеников по имени;
- добавлять новых учеников;
- удалять учеников;
- сохранять данные после перезагрузки страницы.

## Ход работы

### 1. Подготовка проекта

К существующим HTML- и CSS-файлам был добавлен файл `app.js`, в котором реализована вся интерактивная логика приложения.

### 2. Создание начальных данных

В JavaScript был создан массив с первоначальным списком учеников.

Для каждого ученика хранятся следующие данные:

- имя;
- класс;
- предмет;
- цель занятий;
- статус домашнего задания.

### 3. Создание состояния приложения

Для хранения текущих данных был создан объект `state`.

В нем хранятся:

- список учеников;
- текст поискового запроса;
- выбранный предмет;
- выбранный способ сортировки.

### 4. Динамическое отображение учеников

Для работы со страницей использовались возможности DOM: поиск элементов, создание новых элементов, изменение их содержимого и добавление на страницу. После изменения данных вызывается функция `render()`, которая обновляет отображаемый список учеников.

### 5. Реализация поиска

Был реализован поиск учеников по имени и описанию занятий. Поиск выполняется автоматически при вводе текста в поле поиска.

Для того чтобы регистр букв не влиял на результат поиска, введенный текст и данные учеников переводятся в нижний регистр.

### 6. Реализация фильтрации

Для фильтрации учеников был добавлен выпадающий список с выбором предмета.

Можно отобразить учеников по математике, алгебре, информатике или физике.

Также предусмотрен пункт «Все категории», который отменяет фильтрацию и показывает полный список учеников.

### 7. Реализация сортировки

Была добавлена сортировка учеников по имени.

Пользователь может выбрать два варианта:

- от А до Я;
- от Я до А.

Перед выполнением сортировки создается копия массива, поэтому исходный массив учеников не изменяется.

### 8. Создание модального окна

Для добавления нового ученика было создано модальное окно.

Оно открывается после нажатия кнопки «Добавить ученика».

Закрыть окно можно:

- кнопкой-крестиком;
- кнопкой «Отмена»;
- нажатием клавиши Escape;
- кликом по затемненному фону.

### 9. Создание формы добавления ученика

В модальном окне была создана форма для ввода информации о новом ученике.

Форма содержит следующие поля:

- имя ученика;
- класс;
- предмет;
- цель занятий;
- статус домашнего задания.

После заполнения формы новый ученик добавляется в общий список и отображается на странице.

### 10. Реализация валидации формы

Для проверки правильности введенных данных была реализована клиентская валидация.

Использовались HTML5-атрибуты `required`, `minlength`, `min` и `max`.

При попытке отправки формы JavaScript проверяет корректность заполнения каждого поля.

Если данные введены неправильно, под соответствующим полем выводится сообщение об ошибке.

### 11. Реализация удаления учеников

В каждую карточку ученика была добавлена кнопка «Удалить».

Удаление реализовано с помощью делегирования событий.

Один обработчик события установлен на общий контейнер с карточками учеников. После нажатия определяется нужная карточка, после чего ученик удаляется из массива.

### 12. Сохранение данных

Для сохранения списка учеников используется localStorage.

При добавлении или удалении ученика обновленный список сохраняется в браузере.

Перед сохранением данные преобразуются в строку с помощью `JSON.stringify()`.

При загрузке страницы данные восстанавливаются с помощью `JSON.parse()`.

Благодаря этому внесенные изменения сохраняются после обновления страницы.

### 13. Реализация State-Driven UI

Интерфейс приложения формируется на основе объекта `state`.

После изменения поиска, фильтра, сортировки или списка учеников вызывается функция `render()`.

Таким образом, состояние приложения и отображаемая информация всегда соответствуют друг другу.

### 14. Адаптивность интерфейса

Для проекта была сохранена адаптивная верстка из лабораторной работы №1 и добавлены стили для новых элементов.

На больших экранах карточки отображаются в три колонки, на планшетах — в две, а на мобильных устройствах — в одну.

Форма поиска, фильтры и модальное окно также корректно отображаются на экранах разного размера.

## Вывод

В ходе лабораторной работы были получены навыки работы с JavaScript, DOM и пользовательскими событиями.

Были изучены способы динамического изменения содержимого страницы, проверки данных формы, удаления и добавления элементов, а также сохранения информации в localStorage.
